# Isolated XMPP pilot

Use ejabberd Community 25.10 (GPLv2) and the pinned Converse 12.0.0 distribution (MPL-2.0). Run `scripts/xmpp/install-converse.sh` before the pilot app build. It verifies the archive digest, installs the complete dist tree, and publishes the upstream LICENSE and COPYRIGHT alongside the assets. The installer applies a two-template adaptation that removes hardcoded composer autofocus for embedded use. The adaptation source ships alongside the original license in this repository as `scripts/xmpp/remove-composer-autofocus.mjs`. The upstream source is available in the [Converse release](https://github.com/conversejs/converse.js/releases/tag/v12.0.0). See [ejabberd source](https://github.com/processone/ejabberd/tree/25.10).

Use a dedicated real-mode ResponseAble database and synthetic accounts. Create the ejabberd config ConfigMap and TLS/JWK Secret before applying pilot.yaml. Supply a private hostname and a trusted TLS chain for the browser WSS listener. The app must trust the admin TLS chain separately. Keep the admin listener private and authorize only the required affiliation operation.

Keep XMPP_PILOT_ENABLED off until a provisioned room is mapped in xmpp_rooms and the reconciliation endpoint is called periodically. An expired JWT prevents new authorization but does not itself terminate a connection. Test the outcast transition with open clients, reconnect and MAM before enabling a room for real participants. MAM content is readable by the server.

This single replica with a local-path PVC is a pilot, not HA. Verify restart and restore before using it for any durable records.

The pilot uses PostgreSQL only for MAM. Before starting ejabberd, apply archive.yaml with an xmpp-archive-db Secret and initialize the empty database using the pinned ejabberd 25.10 sql/pg.sql (SHA-256 f427948e095ef07c1a7bcd5873e4478d4c40e3897a59172a3bcc0ff5be422754). The ejabberd PVC still holds room metadata and OAuth state. Retain and back up both volumes. This setup does not migrate pre-existing Mnesia archives. After an ejabberd restart, verify the admin bootstrap; if the existing OAuth token is invalid, issue a replacement on the running node, rotate the app Secret and verify again.
